### Node: Application entry and playback

- Type: entry / flow. Status: confirmed.
- Purpose: route open-file and URL investigations to the playback owner.
- Read first: [AppDelegate.swift](../../iina/AppDelegate.swift), `openFile` and `openURL`; [PlayerCore.swift](../../iina/PlayerCore.swift), `openURLs`, `openURL`, `openURLString`.
- Edges: AppDelegate calls PlayerCore.openURLs / openURLString; PlayerCore creates MPVController and MainWindowController and sends the mpv loadfile command.
- Evidence: AppDelegate open actions; PlayerCore initialization around lines 334–335 and loadfile around line 584.
- Branches to inspect only when needed: multiple windows, idle core reuse, file versus network URL, stopping an existing playback before loading another.
- Validation: open a local media file and URL, then repeat with a second window. Not run during initialization.

### Node: UI and native playback boundary

- Type: module / dependency. Status: confirmed.
- Read first: [MainWindowController.swift](../../iina/MainWindowController.swift), [VideoView.swift](../../iina/VideoView.swift), [MPVController.swift](../../iina/MPVController.swift).
- Edges: PlayerCore owns playback; MainWindowController installs the video view; MPVController creates and initializes the native mpv handle. Contribution rules restrict direct mpv calls to MPVController and VideoView.
- Evidence: [CONTRIBUTING.md](../../CONTRIBUTING.md#architecture), PlayerCore initialization, MainWindowController.addVideoViewToWindow, MPVController mpv_create and mpv_initialize calls.
- Unknown: full rendering and shutdown concurrency behavior. Read those paths before changing lifecycle or threading.
- Next drill-down: window open/close, rendering callback lifetime, mpv event dispatch.

### Node: Bundled tools and browser integration

- Type: module / entry. Status: confirmed.
- [iina-cli/main.swift](../../iina-cli/main.swift): parses CLI arguments, locates the IINA executable in its app bundle and launches it with Process; optional stdin and keep-running behavior.
- [iina-plugin/main.swift](../../iina-plugin/main.swift): dispatches new, pack, link and unlink plugin development commands.
- [OpenInIINA](../../OpenInIINA/) and [browser](../../browser/): browser integration entry areas. Xcode declares OpenInIINA as an app-extension target; end-to-end browser dispatch is unknown here.
- Evidence: tool entry files and [project.pbxproj](../../iina.xcodeproj/project.pbxproj) PBXNativeTarget section.
- Validation: use built app-bundle CLI help and smoke-test requested commands; do not assume CLI binaries work outside the app bundle.

### Node: Validation and risks

- Type: validation / risk. Status: confirmed configuration, unverified execution.
- Read first: [CI](../../.github/workflows/ci.yml), [spelling workflow](../../.github/workflows/spelling.yml), [iina scheme](../../iina.xcodeproj/xcshareddata/xcschemes/iina.xcscheme).
- Preparation: `./other/download_libs.sh`.
- Build: `xcodebuild -project iina.xcodeproj ONLY_ACTIVE_ARCH=NO -scheme iina -derivedDataPath . -configuration Nightly` (CI command).
- Tests: no XCTest target found in project.pbxproj; no explicit testables in the shared iina scheme. No automated test command identified. CI spelling uses crate-ci/typos.
- Local limit: xcodebuild cannot run with the currently selected Command Line Tools directory. Neither dependencies nor the application were built during initialization.
- Risks: native dylibs and signing affect builds; generated MPVCommand/MPVOption/MPVProperty files must be regenerated through other/parse_doc.rb; UI and localization edits follow CONTRIBUTING.md.
- Suggested manual checks after code changes: local playback, pause/seek, subtitles, playlist, window close/reopen, and the changed capability.
